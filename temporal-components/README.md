# Temporal Components — Configuration Reference

This folder contains every configuration file and rendered Kubernetes manifest for the
Temporal deployment. It is a **read-only reference** — the live deployment is driven from
`temporal/` via ArgoCD. Edit files in `temporal/`, not here.

---

## Folder Structure

```
temporal-components/
│
├── README.md                        ← this file
│
├── app.yaml                         ← ArgoCD Application definition
├── values.yaml                      ← Helm chart overrides (our config)
├── postgres-visibility.yaml         ← PostgreSQL deployment (raw manifest)
│
└── rendered/                        ← All Kubernetes resources generated by
    │                                  `helm template temporal 0.48.0 -f values.yaml`
    │
    ├── cassandra-statefulset.yaml   ← Cassandra StatefulSet + config
    ├── cassandra-service.yaml       ← Cassandra headless Service
    │
    ├── server-configmap.yaml        ← Temporal server config (Go template)
    ├── server-dynamicconfig.yaml    ← Dynamic config ConfigMap
    ├── server-secrets.yaml          ← Secrets for Cassandra + visibility store passwords
    ├── server-schema-job.yaml       ← One-off Job: creates keyspaces + runs migrations
    ├── server-deployments.yaml      ← 4 Deployments: frontend, history, matching, worker
    ├── server-services.yaml         ← Services for all 4 server components
    ├── server-pdb.yaml              ← PodDisruptionBudgets for frontend + matching
    │
    ├── admintools.yaml              ← Admin tools Deployment + Service (tctl pod)
    └── web.yaml                     ← Web UI Deployment + Service (port 8080)
```

## Key Config Files

### `values.yaml` — Helm Chart Overrides

The complete set of overrides applied on top of the Temporal Helm chart defaults.
Key sections:

| Section | What it does |
|---|---|
| `server.config.namespaces` | Auto-creates `default` namespace on deploy |
| `server.config.persistence.default.cassandra.hosts` | Explicit host list — avoids trailing-comma bug in chart template |
| `server.config.persistence.visibility` | Switches visibility store to PostgreSQL (chart has no Cassandra template for visibility) |
| `cassandra.image.tag: "4.0"` | Upgraded from 3.11.x to fix container-unaware OOM behaviour |
| `cassandra.config.max_heap_size: 512M` | Prevents GC pressure that caused liveness probe timeouts |
| `cassandra.env.MALLOC_CONF` | Caps jemalloc arenas at 4 (default is 4×ncpus = 64 on 16-CPU host) |
| `cassandra.updateStrategy: RollingUpdate` | Ensures config changes roll out automatically |
| `cassandra.livenessProbe / readinessProbe` | 120s initial delay + 30s timeout to survive slow startup |

### `app.yaml` — ArgoCD Application

Defines three sources:

| # | Source | Purpose |
|---|---|---|
| 1 | `go.temporal.io/helm-charts` chart `temporal 0.48.0` | The Temporal Helm chart |
| 2 | `gitops.git` (ref only) | Provides `values.yaml` to source 1 |
| 3 | `gitops.git` path `temporal/manifests` | Raw manifests (PostgreSQL) |

`ignoreDifferences` on `Job.spec.template` prevents ArgoCD failing when the schema
Job's init container image changes (Kubernetes Jobs have immutable spec.template).

> **Important:** Changes to `app.yaml` structure must be applied manually:
> ```bash
> kubectl apply -f temporal/app.yaml
> ```

### `postgres-visibility.yaml` — PostgreSQL for Visibility

A minimal PostgreSQL 14 Deployment + Service deployed as a raw manifest (not via Helm).

**Why PostgreSQL instead of Cassandra for visibility?**
The Temporal Helm chart v0.48.0 configmap template has branches only for Elasticsearch
and SQL — there is no Cassandra branch for the visibility store. Setting
`visibility.driver: "cassandra"` (the chart default) produces an empty visibility
section, and Temporal refuses to start. PostgreSQL is the lightweight alternative.

| Setting | Value |
|---|---|
| Image | `postgres:14` |
| User | `temporal` |
| Password | `temporal` |
| Database (auto-created) | `temporal_visibility` |
| Memory limit | 512Mi |
| Persistence | `emptyDir` (non-persistent, fine for dev/test) |

## Rendered Manifests

All files in `rendered/` are generated with:
```bash
helm template temporal temporal-0.48.0.tgz \
  --namespace temporal \
  -f values.yaml
```

They show the **exact** Kubernetes resources ArgoCD applies. Useful for:
- Understanding what each component creates
- Debugging unexpected resource shapes
- Reviewing what changed between Helm chart versions

### `server-configmap.yaml`

Contains `config_template.yaml` — the Go template that the temporal-server container
processes at startup to produce its final `config.yaml`. The template uses
`{{ .Env.TEMPORAL_STORE_PASSWORD }}` placeholders which are filled from Secrets at
runtime.

Key sections in the config template:

```yaml
persistence:
  defaultStore: default          # → Cassandra
  visibilityStore: visibility    # → PostgreSQL
  datastores:
    default:
      cassandra:
        hosts: "temporal-cassandra"   # explicit — avoids trailing-comma bug
        keyspace: temporal
    visibility:
      sql:
        pluginName: "postgres12"
        connectAddr: "temporal-visibility-postgresql:5432"
        databaseName: "temporal_visibility"
```

### `server-schema-job.yaml`

A Kubernetes Job (`temporal-schema-1`) that runs once to set up all datastores.
Init container sequence:

| Step | Container | Action |
|---|---|---|
| 1 | `check-cassandra-service` | `nc` loop until Cassandra DNS resolves |
| 2 | `check-cassandra` | `cqlsh` loop until Cassandra accepts connections |
| 3 | `create-default-store` | Create Cassandra keyspace `temporal` |
| 4 | `create-visibility-store` | `temporal-sql-tool create-database` → creates `temporal_visibility` in PostgreSQL |
| 5 | `setup-default-store` | `temporal-cassandra-tool setup-schema -v 0.0` |
| 6 | `setup-visibility-store` | `temporal-sql-tool setup-schema -v 0.0` |
| 7 | `update-default-store` | Run all Cassandra schema migrations to latest |
| 8 | `update-visibility-store` | Run all PostgreSQL visibility migrations to latest |

If the Job fails or becomes stuck (e.g. after a Cassandra image change), delete it
and ArgoCD recreates it:
```bash
kubectl delete job temporal-schema-1 -n temporal
kubectl -n argocd patch application temporal --type merge \
  -p '{"operation":{"sync":{"syncStrategy":{"hook":{"force":true}}}}}'
```

### `server-deployments.yaml`

Four Deployments, one per Temporal service. Each pod has three init containers that
block startup until Cassandra and the `temporal` keyspace are ready:

| Init container | Wait condition |
|---|---|
| `check-cassandra-service` | `nc -z temporal-cassandra 9042` |
| `check-cassandra` | `cqlsh ... SHOW VERSION` |
| `check-cassandra-temporal-schema` | `cqlsh ... grep temporal$` (keyspace exists) |

### `server-secrets.yaml`

Two Secrets created by the Helm chart:

| Secret | Key | Value source |
|---|---|---|
| `temporal-default-store` | `password` | `cassandra.config.password` (empty = no auth) |
| `temporal-visibility-store` | `password` | `server.config.persistence.visibility.sql.password` |

These are injected into pods as `TEMPORAL_STORE_PASSWORD` and
`TEMPORAL_VISIBILITY_STORE_PASSWORD` environment variables.

## Ports Reference

| Service | Port | Protocol | Purpose |
|---|---|---|---|
| `temporal-frontend` | 7233 | gRPC | SDK / tctl / workflow API |
| `temporal-frontend` | 7243 | HTTP/JSON | REST API (Temporal 1.25+) |
| `temporal-history` | 7234 | gRPC | Internal — history service |
| `temporal-matching` | 7235 | gRPC | Internal — task queue matching |
| `temporal-worker` | 6939 | gRPC | Internal — system worker |
| `temporal-web` | 8080 | HTTP | Web UI |
| `temporal-cassandra` | 9042 | CQL | Cassandra native protocol |
| `temporal-visibility-postgresql` | 5432 | TCP | PostgreSQL |

## Access

```bash
# Web UI
kubectl port-forward -n temporal svc/temporal-web 8080:8080
# → http://localhost:8080

# gRPC API (for SDK / tctl from outside cluster)
kubectl port-forward -n temporal svc/temporal-frontend 7233:7233

# Admin CLI
kubectl exec -it -n temporal deployment/temporal-admintools -- bash

# Cluster health check
kubectl exec -n temporal deployment/temporal-admintools -- tctl cluster health

# List namespaces
kubectl exec -n temporal deployment/temporal-admintools -- tctl namespace list
```
